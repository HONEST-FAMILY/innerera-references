# 레퍼런스 벤치마크 — 범용 쇼핑몰 솔루션 (이슈 #1874, 2026-11-11)

기획서를 쓰기 전에, 국내 실무자가 이미 익숙한 운영 흐름을 공식 자료로 확인하고 우리 계획과 나란히 놓은 문서다. 화면 번호(U-xx, A-xx)는 `00_골격.md` 번호다.

## 0. 확인 방법과 한계 (먼저 읽기)

- 카페24·스마트스토어센터·쿠팡 윙의 관리자 화면은 판매자 로그인이 있어야 열린다. 그래서 **화면을 직접 열어 캡처하지 못했고**, 각 회사의 공식 도움말·개발자 문서로 흐름을 확인했다.
- 확인 등급을 표마다 적었다.
  - **[공식]** 그 회사가 운영하는 도움말·개발자 문서에서 확인(주소 표기)
  - **[공식 요약]** 공식 문서 주소는 찾았으나 본문을 직접 열지 못해(접속 차단 403) 검색 결과에 나온 본문 요약으로 확인
  - **[지식]** 공식 문서로 확인하지 못함. 도메인 지식 기준이며 **개발자 확인 필요**
- 직접 열리지 않은 곳: 네이버 스마트스토어센터 도움말(help.sell.smartstore.naver.com), 네이버 커머스API 문서(apicenter.commerce.naver.com), 쿠팡 개발자센터 본문(403), 카페24 도움말 본문(403, 검색 요약으로 확인), 국가법령정보센터 조문 본문. 네이버 쪽은 네이버 커머스API 팀이 운영하는 공식 기술지원 저장소(github.com/commerce-api-naver)의 답변과 릴리즈 노트로 대신 확인했다.
- 개발 착수 전에 개발자가 판매자 계정으로 **스마트스토어센터 '발주(주문)확인/발송관리' 화면과 커머스API 문서를 직접 열어** 이 문서의 [지식] 항목을 확정해야 한다(기획서 '남은 일'에 적음).

## 1. 출고·처리 흐름 (대상 필터 → 엑셀 다운 → 일괄 업로드)

|---|---|---|---|
| 카페24 [공식 요약] | 메뉴가 주문 상태별로 나뉜다: 입금 전 관리 → 배송 준비 중 관리 → 배송 대기 관리 → 배송 중 관리 → 배송 완료 조회. 메뉴에 들어가면 그 상태 주문만 보인다. | 카페24 [공식 요약] | 택배사 연동을 해 두면 목록 위 '송장번호 일괄받기' 한 번으로 주문마다 송장번호가 자동으로 채워진다 | D5: 2단계에 굿스플로 등 송장 자동 발급 연동. 1단계는 택배사 프로그램에서 출력 후 엑셀 일괄 업로드 | 1단계에 빼는 근거: 택배사 계약·연동 심사가 고객사마다 다르고 12/31 일정 안에 불가. 엑셀 일괄 업로드로 하루 200건을 클릭 7회 안에 처리 가능(기획서 여정 ①) |
| 스마트스토어센터 [지식] | '발주(주문)확인/발송관리': 신규주문 → **발주확인**(누르면 배송준비 상태, 구매자가 바로 취소 못 하고 '취소 요청'이 됨) → 송장 입력(목록 직접 입력 / **엑셀 일괄발송**) → 발송처리. 발송기한을 넘길 것 같으면 **발송지연 안내**(사유·발송예정일 입력, 주문당 1회) → 구매자에게 자동 안내. 기한 넘기면 판매자 불이익 | A-12에 같은 순서로 구현: 일괄 발주확인 → 송장(엑셀·직접 입력) → 발송 처리, 발송 지연 처리 팝업(사유·예정일 → 고객 알림) | 같다. 발주확인을 별도 단계로 두는 이유(확인됨, 아래 행): 발주확인 뒤 취소는 '요청 → 승인'이 된다. 발송기한 일수·불이익 기준은 [지식]이라 설정값(A-93 '발송 기한 영업일', 기본 3)으로 두고 숫자는 고객사가 정한다 |

([#529](https://github.com/commerce-api-naver/commerce-api/discussions/529)) | 여정 ②: 스마트스토어 주문을 우리 A-12에서 자사몰 주문과 **한 목록**으로 발주확인·송장 입력 → 저장 즉시 네이버로 발주확인·발송처리 전송(A-70 전송 기록, 실패 재전송) | 같다. 우리 택배사 목록에 '네이버 택배사 코드'를 함께 저장해 매칭 오류를 막는다(코드 표는 [지식] — 개발자가 문서에서 가져옴) |

| 카페24 [공식 요약] | 한 주문의 품목을 서로 다른 송장으로 보낼 수 있다(부분 배송) ([품목·수량별 송장](https://support.cafe24.com/hc/ko/articles/17081876528025)) | 송장(shipments)과 품목 주문을 '송장-품목' 표로 연결. 한 주문 여러 송장(부분 발송), 여러 주문 한 송장(합포장) 둘 다 가능 | 같다(데이터 모델에서 검증) |
| 스마트스토어·카페24 [지식] | 같은 수령인·같은 주소 주문은 목록에서 묶음으로 표시되고, 묶음 단위로 송장 하나를 넣는다 | A-12 '합포장 묶음 표시': 수령인 이름+연락처+주소가 같은 미발송 주문을 묶음으로 표시, 묶음 선택 시 송장 1개가 전 품목에 적용 | 같다. 배송비를 두 번 받은 합포장은 자동 환불하지 않고 운영자가 '배송비 환불' 버튼으로 처리. 근거: 자동 환불은 판단 착오 시 되돌릴 수 없음 |

## 2. 배송 추적·배송완료·구매확정

| 레퍼런스 서비스 | 그쪽 흐름 | 우리 계획 | 차이와 결정 |
|---|---|---|---|
| 카페24 [공식 요약] | 배송 후 자동으로 배송완료가 되게 하는 설정이 있고, '구매 확정 자동체크'로 운영자가 정한 기간이 지나면 자동 구매확정된다. ([구매 확정](https://support.cafe24.com/hc/ko/articles/17071547212825), [주문 후 설정](https://support.cafe24.com/hc/ko/articles/7751230733081)) | 배송 추적 API로 배송완료 자동 반영 → 배송완료 N일 뒤(기본 7일, A-93에서 1~30일) 자동 구매확정 | 같다 |
| 스마트스토어 [지식] | 배송 추적이 되는 택배는 배송완료 후 일정 기간(통상 8일째)에 자동 구매확정. 추적이 안 되는 직접전달 등은 발송 후 더 긴 기간 뒤 자동 확정. 구매확정이 정산 기준 | 추적 가능한 택배 = 배송완료 + N일. **추적 불가(직접 배송·퀵·추적 실패)** = 발송 후 M일(기본 14일) 뒤 자동 배송완료 처리 후 N일 뒤 확정. 운영자 수동 배송완료·수동 확정(A-13, A-14) 가능 | 스마트스토어 주문은 구매확정을 네이버가 정하므로 **우리가 자동 확정하지 않고 네이버 상태를 받아 반영**한다 |
| 딜리버리트래커 [공식] | 조회는 택배사 ID+송장번호로 요청(보통 1초 미만, 타임아웃 15초 권장). **주기적으로 반복 조회(폴링)는 권장하지 않고 웹훅 등록을 쓰라**고 안내. 웹훅은 만료 시각을 '지금+48시간'으로 걸고 24시간마다 다시 등록해 갱신 권장. 콜백에는 택배사·송장번호만 오므로 받은 뒤 다시 조회해야 한다. 콜백 서명 검증은 기본 제공되지 않는다 ([Tracking API](https://tracker.delivery/docs/tracking-api), [Webhook](https://tracker.delivery/docs/tracking-webhook-api)) | 발송 처리 시 웹훅 등록 → 콜백이 오면 대기열에 넣고 조회해 상태 반영 → 배송완료까지 매일 한 번 웹훅 재등록(자동). 콜백 내용은 믿지 않고 반드시 다시 조회 | 요금·지원 택배사·상태 코드 목록은 이번에 확인 못 함 → **[지식] 개발자 확인 필요**. 대안으로 스마트택배(스윗트래커) API도 같은 구조로 끼울 수 있게 '배송 추적 연결'을 교체 가능한 부품으로 만든다(대표 확인 항목) |

## 3. 클레임 (취소·반품·교환·환불 + PG 실환불)

| 레퍼런스 서비스 | 그쪽 흐름 | 우리 계획 | 차이와 결정 |

## 11. 벤치마크 결론 — 기획서에 반영한 것

1. 주문 메뉴는 상태별 '처리 화면'으로 나눈다(카페24·스마트스토어 공통). 들어가면 처리할 것만 보인다.
2. 발주확인을 별도 단계로 둔다. 발주확인 전 = 고객 즉시 취소, 후 = 요청·승인(스마트스토어·쿠팡 공통).
3. 송장은 엑셀 일괄 업로드가 기본 동선이고, 올리면 행별 검증 결과를 보여 준다(카페24보다 한 단계 더).
4. 취소 요청이 걸린 품목은 출고에서 자동 제외한다(쿠팡 출고중지요청).
5. 환불완료 표시는 PG 응답 뒤에만 바뀐다. 잔액 검증 값을 같이 보내 중복 환불을 막는다(포트원).
6. 가상계좌 환불은 특약·수수료·환불 계좌가 필요하다 → 설정 스위치와 수동 경로를 같이 둔다.
7. 스마트스토어 주문은 결제·환불·구매확정·구매자 알림을 네이버가 한다. 우리는 수집·출고·상태·재고만.
8. 알림톡은 템플릿 심사가 있다 → 문구 편집 화면에 심사 상태, 미승인 시 문자 대체.
9. 품목(판매 단위)과 실물 재고를 분리한다(구성 옵션 실사례).
10. 휴면은 법정 의무가 아니다 → 선택 기능.
11. 스마트스토어 연동 자격은 착수 전에 네이버에 확인한다.
