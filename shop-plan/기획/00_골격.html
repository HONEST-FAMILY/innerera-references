범용 쇼핑몰 솔루션 기획 골격 (이슈 #1874, 2026-11-11)

이 문서는 기획서·기능정의서·와이어프레임이 함께 따르는 약속이다. 화면 번호(U-xx, A-xx)와 화면 상태 목록은 와이어프레임 사이트맵과 1:1로 맞춘다. 기획서를 쓰다 화면을 더하거나 빼야 하면 이 문서부터 고친다.

0. 한 줄 정의

어니스트패밀리가 쇼핑몰 의뢰가 들어올 때마다 다시 쓰는 자체 쇼핑몰 솔루션. 1호 적용은 이너에라(Inner:Era) 공식몰. 고객사 운영자가 개발자 없이 상품·주문·배송·고객응대·전시·설정을 처리하고, 카페24·스마트스토어 판매자센터에서 일하던 실무자가 처음 봐도 바로 쓸 수 있는 관리자.

1. 확정 결정 (대표 확인 전 가정 — 기획서 '확정 결정사항'에 그대로 옮기고, 뒤집히면 영향 범위를 적는다)

# 결정 내용 이유
D1 자체 개발 카페24·아임웹 대신 자체 코드. 회사 표준(백엔드 Laravel API + 프론트 React/Next.js, 관리자는 같은 프론트의 /admin) 대표 지시 "앞으로 쇼핑몰마다 재활용"
D2 1고객사 1설치 코드 하나, 고객사마다 서버·DB·도메인 따로. 고객사별 차이는 '설정'과 '기능 켜고 끄기'로 흡수 개인정보 분리, 고객사별 맞춤이 쉬움. 여러 고객사를 한 DB에 넣는 방식은 지금 수요 대비 과함
D3 기능 켜고 끄기 적립금 · 쿠폰 · 회원등급 · 리뷰 · 상품문의 · 비회원 주문 · 스마트스토어 연동 · 정기배송(2단계)을 관리자 설정에서 켜고 끈다. 꺼진 기능은 사용자 화면·관리자 메뉴·알림에서 함께 사라진다 고객사마다 쓰는 기능이 다름
D4 결제 포트원(PortOne) V2 를 거쳐 PG 연동: 카드 · 실시간 계좌이체 · 가상계좌 · 카카오페이 · 네이버페이 · 토스페이. 취소·부분취소·가상계좌 환불은 관리자 처리 시 PG 취소 API 자동 호출. PG 계약·심사는 고객사 몫 PG사를 바꿔도 코드 그대로, 국내 쇼핑몰 표준
D5 배송 택배사 여러 곳. 송장은 ① 엑셀 일괄 업로드 ② 목록에서 바로 입력 ③ (2단계) 굿스플로 등 송장 자동 발급 연동. 배송 추적은 택배 조회 API로 배송완료 자동 반영, 배송완료 N일 뒤 자동 구매확정 하루 수십~수백 건을 한 건씩 입력하면 실무가 안 됨(대표 지적)
D6 알림 카카오 알림톡(문자 대행사 경유) 기본, 실패 시 문자로 대체, 이메일 병행. 알림마다 켜고 끄기·문구 편집. 내부 수신자(신규 주문·문의 알림 받을 운영자 메일·휴대폰)는 관리자에서 설정 화면에 안 보여 빠지기 쉬움, 담당자 바뀌면 고쳐야 함
D7 회원 이메일 가입 + 카카오·네이버 간편 로그인(부족한 항목만 추가 입력) + 비회원 주문(주문번호 + 휴대폰 번호 + 주문 비밀번호로 조회). 휴대폰 본인인증은 켜고 끄기 전환율, 개인정보 최소 수집
D8 스마트스토어 연동 네이버 커머스API: ① 우리 몰 상품을 스마트스토어로 등록·가격·재고 동기화 ② 스마트스토어 주문을 우리 관리자 주문 목록으로 수집(채널 = 스마트스토어) → 같은 화면에서 발주확인·송장 입력 → 스마트스토어로 발송처리 전송 ③ 취소·반품·교환 요청 수집과 처리 결과 전송. API 키 발급은 고객사 몫 계약 범위 '네이버 스마트스토어 연동'. 두 곳 주문을 한 화면에서 출고해야 실무가 줄어듦
D9 상품 구조 상품 → 옵션(조합형: 옵션 축 최대 3개, 축 이름·값을 상품마다 자유롭게 / 단독형) → 품목(SKU)별 재고·추가금·판매상태. 추가구성상품. 상품정보제공고시는 품목군 템플릿(공정위 고시 품목군). 배송비는 '배송비 템플릿'을 상품에 연결 업종이 바뀌어도(식품·화장품·의류·꽃) 축이 다른 상품을 다 담기 위해 — 축을 컬럼으로 고정하지 않음
D10 정기배송 2단계. 1단계에서는 데이터 자리만 비워 둔다(빌링키 결제 필요) 1단계 일정 안에 무리
D11 화면 사용자 화면은 PC·모바일 반응형(모바일 하단 탭바), 관리자는 PC 1280 이상 기준(모바일에서는 주문 확인·문의 답변만 쓸 수 있게) 실무는 PC, 사장님은 폰으로 확인
D12 디자인 사용자 화면은 고객사 시안(이너에라 shop-1·detail-1)을 입힘. 메인·브랜드·원료 이야기 같은 콘텐츠는 관리자 '메인 화면 구성'·'콘텐츠 페이지' 블록으로 조립 다음 고객사는 블록과 디자인 토큰만 바꿔 재사용
